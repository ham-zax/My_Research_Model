# BTC spot reference audit before fitting

Recorded 2026-09-23, before reading the additional 2025-04-01 and 2025-05-01 quote files. Development-only sample dates are fixed as 2025-03-01, 2025-04-01, and 2025-05-01, the first three consecutive free monthly samples starting with the already acquired day. These sparse dates are not a development backtest or a representative stress sample.

The user approved a provisional two-venue midpoint reference with a five-second maximum quote age. At integer UTC seconds, use each venue's latest received valid BTCUSDT spot quote, calculate `(bid + ask) / 2`, then average the two midpoints with equal weights. Preserve microsecond event and receipt timestamps. Require both constituents, positive finite prices and sizes, bid below ask, receipt no later than the grid boundary, event no later than receipt, and event age at most five seconds. Process quote states in capture order, using CSV row order for ties. An invalid newer quote invalidates that constituent until a valid newer state arrives; never fall back to an earlier valid quote.

Compare 1, 2, 5, and 10 seconds for **data quality only**: valid grid counts, longest valid and invalid stretches, number of complete 30-minute grid windows, spread and cross-venue midpoint disagreement. Fix the primary five-second candidate before extracting its events and labels. Do not select a rule using returns, label balance, prediction scores or hypothetical profit. Preserve the older trade-based feasibility output.

An unchanged top quote may remain executable while deeper book levels change. The preferred eventual validity test reconstructs each spot book and checks sequence continuity, connection status, resynchronization and source progress. Tardis quote CSVs omit disconnect markers, so a five-second cap is an explicit approximation and does not certify feed health. No future interpolation, source substitution, inferred receipt time or liveness claim is allowed. Spread and disagreement are diagnostics until separate exclusion thresholds are specified; they do not silently remove difficult market states.

Evidence: [quote schema and update semantics](https://docs.tardis.dev/downloadable-csv-files/data-types.md#quotes), [CSV access and omitted disconnect messages](https://docs.tardis.dev/downloadable-csv-files/api.md), [capture order and nonmonotonic exchange timestamps](https://docs.tardis.dev/faq/data.md). Any later live-feed or three-venue robust composite requires an explicit versioned definition; more complexity is not justified by this coverage audit alone.
